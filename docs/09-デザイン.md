# デザイン — トークン・レイアウト・アニメーション

実装は `app/frontend/styles.css` にある。
このファイルは「なぜその値なのか」と「やってはいけないこと」を残すためのもの。

値を変えるときは、最後の「してはいけないこと」に反していないか確認する。

---

## 1. 何を直したかったのか

刷新前の画面には、具体的な問題が4つあった。

| 問題 | 原因 |
|---|---|
| 中央に詰まって両脇が空く | `.container` が `max-width: 44rem` の中央寄せ1カラム |
| 1件で画面が埋まり、探せない | 一覧のカードが解説全文＋例を出していた |
| タグが団子になる | 各タグの `margin` 頼みで、折り返すと間隔が崩れる |
| 視線の起点が無い | 単語名 1.1rem と本文 1rem がほぼ同じ大きさ |

**「色が古い」ことは問題ではなかった。**
色と角丸は仕上げであって、上の4つはそれでは1ミリも改善しない。
順序としては、構造 → 階層 → 仕上げ。

## 2. レイアウト

```
┌──────────┬────────────────────────┐
│ サイドバー │  本文                   │
│  20rem    │  max-width 46rem        │
│          │                        │
│ 追加     │  選んだ単語の解説        │
│ 検索     │                        │
│ タグ絞込  │                        │
│ 単語一覧  │                        │
│ ─────    │                        │
│ アカウント │                        │
└──────────┴────────────────────────┘
```

**探す場所（サイドバー）と読む場所（本文）を分ける。**
一覧を固定したことで、単語が何件になっても探す手間は変わらない。
以前は解説が縦に積まれていたため、件数に比例してスクロール量が増えていた。

### 幅の考え方

- **サイドバー 20rem 固定** … 探す場所。単語名と1行要約が入れば足りる
- **本文 max-width 46rem** … 読む場所。1行が長すぎると、行末から次の行頭へ目線を戻せなくなる

**幅を制限するのは本文だけ。** 一覧は基準が違う（読むのではなく見渡す）ので制限しない。

### スマホ（768px 未満）

URLで表示を切り替える。ドロワー（重なって出るメニュー）にはしない。

| URL | 表示 |
|---|---|
| `/` | サイドバーのみ |
| `/terms/:id` | 本文のみ ＋「← 一覧に戻る」 |

**理由**：ドロワーは「開いているか」という、URLに現れない状態を増やす。
その状態は再読み込みで消え、ブラウザの戻るでも復元されない。
URLと1対1にすれば、戻るボタンがそのまま「一覧に戻る」になり、
詳細URLを共有すればその単語が開いた状態で始まる。**状態を持たないのが一番壊れない。**

## 3. トークン

### 間隔 — 4px スケール

| トークン | 値 | px |
|---|---|---|
| `--space-1` | 0.25rem | 4 |
| `--space-2` | 0.5rem | 8 |
| `--space-3` | 0.75rem | 12 |
| `--space-4` | 1rem | 16 |
| `--space-5` | 1.25rem | 20 |
| `--space-6` | 1.5rem | 24 |
| `--space-8` | 2rem | 32 |

**px ではなく rem で書く理由**：
見た目の刻みは4pxのままだが、単位は rem にしている。
px で書くと、ブラウザの文字サイズ設定を大きくしている人の画面で
「文字だけ大きくなり余白は据え置き」になってレイアウトが潰れる。
rem なら余白も一緒に伸びる。既定16pxなので `0.25rem = 4px`。

### 角丸 — 入れ子で 4px ずつ減らす

| トークン | 値 | 使う場所 |
|---|---|---|
| `--radius-1` | 4px | 最内：タグ、バッジ |
| `--radius-2` | 8px | ボタン、入力欄、一覧の行 |
| `--radius-3` | 12px | カード |
| `--radius-4` | 16px | 最外：パネル |

**理由**：入れ子の角丸は `内側 = 外側 − 余白` にすると曲線が同心円になり、平行に見える。
同じ値を使い回すと、内側の角が相対的に丸くなりすぎてずれて見える。
余白が4px刻みなので、角丸も自動的に4px刻みで減る。
**迷ったら「1つ内側なら1段小さく」。**

> タグはかつてピル型（999px）だった。この規則に統一した結果 4px になった。
> 例外を作ると「統一されている」という前提自体が崩れるため、規則を優先した。

**画面端に接する要素は丸めない。**
サイドバーやヘッダーを丸めると、背景との間に三角の隙間ができて雑に見える。
角丸は「浮いているもの」に付ける。

### 文字

| トークン | 値 | px | 用途 |
|---|---|---|---|
| `--text-sm` | 0.875rem | 14 | 補助テキスト。**これが下限** |
| `--text-base` | 1rem | 16 | 本文 |
| `--text-lg` | 1.125rem | 18 | 単語名 |
| `--text-xl` | 1.375rem | 22 | 詳細の見出し |

**14px を下回らせない。** これより小さいと日本語の漢字が潰れて読めない。
刷新前の `.muted` は 0.88rem（14.08px）で、辛うじて満たしていたが根拠が無かった。

入力欄だけは `font-size: 16px` を直接指定している。
iOS Safari は16px未満の入力欄をタップすると自動でズームするため。

### 色

**青は「操作できるもの」だけに使う。**

| 用途 | トークン |
|---|---|
| 操作できるもの | `--accent` `--accent-hover` `--accent-soft` |
| 地・面 | `--bg` `--surface` `--surface-2` |
| 文字 | `--text` `--muted` |
| 状態 | `--success`（完了）`--warning`（生成中）`--danger`（失敗） |

**面を青で塗らない理由**：解説文を読むアプリなので、色面が広いと目が疲れて読めなくなる。
青を塗るのはリンク・主ボタン・選択中の行・フォーカス枠だけ。

**状態色を青から独立させた理由**：
刷新前は「完了」が主色と同じ色だった。
主色を画面のあちこちで使うと、「完了」の色がただの装飾に埋もれて状態を示さなくなる。
**状態を示す色は、他の用途で使っていない色である必要がある。**

**地が寒色グレーな理由**：青と暖色グレー（茶寄り）を並べると濁る。色相を揃える。

ダークモードでは青を明度の高いものに差し替える。`#2563eb` は暗い地の上では沈んで読めない。

## 4. アニメーション

### 規則

> **状態が変わったことを見落とすと困る場所にだけ付ける。**
> **位置も存在も既に分かっているものには付けない。**

### 付ける場所（これで全部）

| 場所 | 長さ | なぜ必要か |
|---|---|---|
| AI生成の完了 | `--dur-base` 150ms | 自分が操作していないのに変わる。瞬時だと見落とす |
| トースト通知 | `--dur-slow` 200ms | 突然出ると驚き、突然消えると見落とす |
| ホバー・フォーカス | `--dur-fast` 100ms | 押せることのフィードバック。長いと操作が重く感じる |
| （予定）サイドバー開閉 | `--dur-slow` 200ms | どこから出てきたかを示す |

`.status.pending` の点滅も残している。これは装飾ではなく
「今まさに動いている」という情報で、止まって見えると故障と区別がつかない。

### 動きを減らす設定への対応

`prefers-reduced-motion: reduce` のとき、全てのアニメーションを打ち消す。
`styles.css` の末尾に一括で置いてある。

**個々の指定に `@media` を書かない。** 新しくアニメーションを足したときに
対応を忘れる。末尾で一括して打ち消せば書き漏らしが起きない。

## 5. してはいけないこと

守らないと、統一されているという前提そのものが壊れる。

### レイアウト

- **一覧の行に解説全文を出さない。** 1行要約まで。全文は本文側で読む
- **本文の `max-width` を外さない。** 1行が長いと読めなくなる
- **サイドバーに `max-width` を付けない。** 探す場所は読む場所と基準が違う

### 間隔・角丸

- **4px の倍数以外を使わない。** `0.6rem`（9.6px）のような値を足さない
- **`px` で余白を書かない。** 文字サイズ設定に追従しなくなる
- **角丸に例外を作らない。** ピル型に戻したくなっても、規則を優先する
- **画面端に接する要素を丸めない**

### 色

- **状態色（完了・生成中・失敗）を青にしない。** 状態が伝わらなくなる
- **面を青で塗らない。** 読めなくなる
- **`--text-sm`（14px）より小さい文字を使わない**
- **新しい色を直接書かない。** 必ずトークンとして定義してから使う

### アニメーション

- **一覧の行に入場アニメーションを付けない。** スクロールのたびにチラついて、探す作業を邪魔する
- **ページ遷移にフェードを付けない。** 体感速度が落ちる。単語帳は速さが価値
- **装飾目的の動きを付けない**
- **`prefers-reduced-motion` の打ち消しを消さない**

### 安全性

- **AIの出力を `v-html` で描画しない。** `{{ }}` は自動エスケープされる
  （詳細は `TermCard.vue` のコメント、および `CLAUDE.md` の「守るべき原則」）
