# デプロイ — Fly.io で公開する

**この作業だけは、あなた自身が実行する必要があります**
（ブラウザ認証と支払い方法の登録が必要なため）。

設定ファイル（`Dockerfile` / `fly.toml`）は用意済みです。

---

## 0. 公開する前に理解しておくこと

**公開した瞬間、あなたのURLは世界中のボットにスキャンされます。**

このアプリは特に注意が要ります：

> **あなたのAPIキーで動くアプリなので、破られると他人があなたの財布で Claude を叩けます。**

そのために既に対策済みのもの：

| 対策 | 場所 |
|---|---|
| 全エンドポイントが認証必須（既定で保護） | `ApplicationController` |
| bcrypt（コスト12）でパスワードを保護 | `User` |
| httpOnly / Secure / SameSite=Lax な Cookie | `session_store.rb` |
| CSRFトークンの検証 | `ApplicationController` |
| Sidekiq管理画面もログイン必須 | `routes.rb` |
| 他人のデータには404（列挙攻撃対策） | `TermsController` |

**あなたがやるべきこと**：`.env` の `SEED_USER_PASSWORD` を
**推測できない長いものに変える**こと。ここが唯一の入口です。

## 1. Fly CLI のインストールとログイン

```powershell
# Windows (PowerShell)
iwr https://fly.io/install.ps1 -useb | iex
```

> **Windows でハマった点（2026-07-20 に実際に踏んだ）**
>
> - インストール直後の PowerShell では `fly` が「認識されません」になる。
>   永続 PATH には登録されるが、**起動済みのシェルには反映されない**。
>   開き直すか、そのセッションだけなら:
>   `$env:PATH += ";$env:USERPROFILE\.fly\bin"`
> - `fly.exe` が **0バイトの壊れたファイル**として作られることがある。
>   `flyctl.exe`（約113MB）が本体で、`fly.exe` はそこへのリンクのはずが
>   作成に失敗した状態。シェルを開き直しても `fly` は動かない。
>   `flyctl` を使うか、ハードリンクを張り直す:
>   ```powershell
>   $bin = "$env:USERPROFILE\.fly\bin"
>   Remove-Item "$bin\fly.exe" -Force
>   New-Item -ItemType HardLink -Path "$bin\fly.exe" -Target "$bin\flyctl.exe"
>   ```

```powershell
fly auth signup   # 初回
fly auth login    # 2回目以降
```

> ⚠️ **無料枠は廃止されている（2026-07-20 時点で確認）**
>
> このドキュメントには以前「無料枠内なら請求されません」と書いていたが、
> **Fly.io は新規ユーザー向けの無料プランを廃止した**（既存ユーザーのみ猶予）。
> カード未登録の組織はマシン作成枠がほぼ無く、
> `fly launch` が次のエラーで止まる:
>
> ```
> requested machine count exceeds organization limit
> Error: payment method required to continue
> ```
>
> **このアプリの構成でかかる費用**
>
> | 項目 | 概算 |
> |---|---|
> | app マシン（512MB） | 約 $3.2〜4.2/月。アイドル時は自動停止するので実際は安い |
> | worker マシン（512MB） | 約 $3.2〜4.2/月。**自動停止しないので満額かかる** |
> | Postgres | プラン次第（別料金） |
> | Redis（Upstash） | 使用量課金 |
>
> worker が満額なのは、`fly.toml` の `auto_stop_machines` が
> `processes = ["app"]` にしか掛かっていないため。
> Sidekiq が止まるとジョブが処理されないので、これは設計として正しい。
>
> 費用を半分にしたい場合は worker を app と同じマシンに同居させる手もある。
> 「AI生成は別プロセス」という設計判断（CLAUDE.md）は、
> Railsのリクエスト枠を占有しないことが目的なので、
> **同一マシン上の別プロセスであれば守れる**。
> ただし512MBに Puma と Sidekiq を同居させるとメモリが厳しく、
> 片方が落ちるともう片方も巻き添えになる。
>
> 最新の料金は https://fly.io/docs/about/pricing/ で確認すること。

## 2. アプリの作成

```bash
cd C:\dev\memo
fly launch --no-deploy
```

対話で聞かれます：

| 質問 | 答え |
|---|---|
| Would you like to copy configuration? | **Yes**（用意した `fly.toml` を使う） |
| App name | 世界で一意な名前（例: `yazyu-memo-words`） |
| Region | **Tokyo (nrt)** |
| Postgres / Redis を作るか | **No**（次の手順で自分で作ります） |

`--no-deploy` は「設定だけ作って、まだデプロイしない」の意味です。
DBとRedisを先に用意する必要があります。

---

## 3. PostgreSQL と Redis を用意する

```bash
# PostgreSQL
fly postgres create --name memo-db --region nrt --initial-cluster-size 1 \
  --vm-size shared-cpu-1x --volume-size 1

# アプリに接続（DATABASE_URL が自動で設定される）
fly postgres attach memo-db --app <あなたのアプリ名>

# Redis（Upstash）
fly redis create --name memo-redis --region nrt
```

Redis作成後に表示される接続URLを控えて、次で登録します。

> **なぜ `attach` で DATABASE_URL が自動設定されるのか**
> `config/database.yml` を最初から `ENV.fetch("DATABASE_URL")` にしてあるので、
> **コードを1文字も変えずに本番へ移れます。**
> これが「設定はコードではなく環境に置く」の効果です。

## 4. 秘密情報を登録する

```bash
fly secrets set \
  ANTHROPIC_API_KEY="sk-ant-api03-..." \
  SECRET_KEY_BASE="$(docker compose exec -T web rails secret)" \
  REDIS_URL="redis://default:xxxxx@fly-memo-redis.upstash.io:6379" \
  SEED_USER_EMAIL="あなたのメールアドレス" \
  SEED_USER_PASSWORD="十分に長い推測されないパスワード" \
  --app <あなたのアプリ名>
```

**`fly secrets` は暗号化して保存され、`fly.toml`（Gitにコミットされる）には残りません。**

| 変数 | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | AI呼び出し |
| `SECRET_KEY_BASE` | セッションCookieの署名鍵。**これが漏れると誰でもなりすませます** |
| `REDIS_URL` | ジョブキューとWebSocketのpub/sub |
| `SEED_USER_*` | あなたのアカウント作成用 |

## 5. Host Authorization の設定

Rails 8 は Hostヘッダを検査し、許可リストにないと403を返します（DNSリバインディング対策）。
本番のドメインを許可する必要があります。

`config/environments/production.rb` に追記：

```ruby
config.hosts << "<あなたのアプリ名>.fly.dev"
# 独自ドメインを使うなら、それも追加
# config.hosts << "memo.example.com"
```

**これを忘れると、デプロイは成功するのに全アクセスが403になります。**

## 6. デプロイ

```bash
fly deploy
```

初回は5〜10分かかります。内部で起きること：

```
① Dockerfile でイメージをビルド（マルチステージ）
② Vue をビルドして public/vite/ に出力
③ イメージをFly.ioへ転送
④ release_command で rails db:migrate を実行
⑤ app プロセスと worker プロセスを起動
```

## 8. 動作確認

```bash
fly open      # ブラウザで開く
fly logs      # ログを見る
fly status    # マシンの状態
```

**確認する項目：**

- [ ] ログインできる
- [ ] 単語を登録すると「生成中…」のカードが出る
- [ ] **数秒後にリロードせずに解説が表示される**（← WebSocketが動いている証拠）
- [ ] スマホから開ける
- [ ] `https://` になっている（鍵アイコン）

## トラブルシューティング

| 症状 | 原因 |
|---|---|
| 全アクセスが403 | `config.hosts` に本番ドメインを追加していない |
| ログインできない（Cookieが保存されない） | `force_https = true` になっていない |
| 「生成中…」のまま止まる | worker が起動していない → `fly status` で確認 |
| WebSocketが繋がらない | `REDIS_URL` が未設定、または `cable.yml` の production 設定 |
| 500エラー | `SECRET_KEY_BASE` 未設定 |
| AI生成が401で失敗 | `ANTHROPIC_API_KEY` 未設定、または残高不足 |

```bash
# 設定済みのsecret一覧（値は表示されません）
fly secrets list

# ワーカーだけのログ
fly logs --app <アプリ名> | grep worker
```

## 料金の目安

| 項目 | 月額 |
|---|---|
| app マシン（auto_stop有効） | ほぼ0円 |
| worker マシン（常時起動） | 約200〜300円 |
| PostgreSQL（1GB） | 無料枠内 |
| Redis（Upstash 無料枠） | 0円 |

**合計：月300〜400円程度。**

### さらに安くしたい場合

`worker` も auto_stop の対象にできますが、
**止まっている間はジョブが処理されません**。
「登録してから数分後に解説が出る」ことを許容できるなら選択肢になります。

## 最後に

デプロイが済んだら、**最初に登録する単語は「冪等性」**にしてみてください。

このアプリの中で、あなたは既にその概念を3回実装しています：

1. `db/seeds.rb` の `find_or_create_by!`（何度実行しても同じ結果）
2. `ExplainTermJob` の `unless term.pending?`（二重実行への備え）
3. `TermTag.find_or_create_by!`（同じタグを二重に付けない）

AIの解説と、自分が書いたコードを見比べてみると、
「調べた知識」が「使った経験」と繋がります。
